# 成员同步仓库配置指南

## 1. 仓库角色

本项目有两个远程仓库：

- `origin`：猿舟平台上的 GitLab 仓库，主仓库，所有正式代码以这里为准。
- `github`：GitHub 私有仓库，用于在线浏览、备份和协作查看。

两个仓库不会自动同步。推荐由仓库负责人负责把猿舟的最新提交同步到 GitHub。

> 猿舟是 GitLab Community Edition。GitLab 中与 GitHub Pull Request 对应的功能叫 **Merge Request（合并请求，简称 MR）**。猿舟帮助页明确提供 Merge Request 功能；具体项目是否启用以及成员是否有创建权限，以项目页面和成员权限为准。

---

## 2. 成员权限分工

### 有 GitHub 账号的成员

可以：

- 从猿舟拉取代码；
- 向猿舟提交代码；
- 接受 GitHub 私有仓库邀请并在线查看代码。

日常仍以猿舟为提交入口，不建议直接在 GitHub 网页编辑代码。

### 没有 GitHub 账号的成员

只需要配置猿舟远程仓库：

- 从猿舟拉取代码；
- 向猿舟提交代码；
- 不需要配置 `github` 远程。

仓库负责人会把猿舟的提交同步到 GitHub。

---

## 3. 第一次获取项目

安装 Git 后，在保存项目的目录打开终端：

```bash
cd /d D:\laptop-learning\企业实训\project
git clone <猿舟仓库地址>
cd issedu_ysu2026_7439
```

检查当前远程：

```bash
git remote -v
```

成员只提交猿舟时，应该看到：

```text
origin  <猿舟仓库地址> (fetch)
origin  <猿舟仓库地址> (push)
```

不要把包含 Token 的完整 URL 写进文档、群聊或提交记录。认证时按猿舟平台要求使用 Token，优先使用 Git Credential Manager 或 SSH Key 保存凭据。

---

## 4. 有 GitHub 账号的成员配置 GitHub 远程

先接受仓库负责人发出的 GitHub 私有仓库邀请，然后进入本地项目：

```bash
cd /d D:\laptop-learning\企业实训\project\issedu_ysu2026_7439
```

添加 GitHub 远程：

```bash
git remote add github https://github.com/<GitHub用户名>/<仓库名>.git
```

例如：

```bash
git remote add github https://github.com/example/issedu_ysu2026_7439.git
```

确认：

```bash
git remote -v
```

应该包含：

```text
origin  <猿舟仓库地址> (fetch)
origin  <猿舟仓库地址> (push)
github  https://github.com/<GitHub用户名>/<仓库名>.git (fetch)
github  https://github.com/<GitHub用户名>/<仓库名>.git (push)
```

GitHub 使用 HTTPS 推送时，密码位置应使用 GitHub Personal Access Token，不要使用 GitHub 账号密码。

## 5. 每次开发前

先确认自己没有未提交修改：

```bash
git status
```

如果工作区干净，拉取猿舟最新代码：

```bash
git pull --ff-only origin master
```

如果提示无法快进，先不要使用强制命令。执行：

```bash
git status
git log --oneline --decorate --graph --all -10
```

并联系仓库负责人处理。

---

## 6. 每次完成开发后

```bash
git status
git add <实际修改的文件>
git commit -m "清晰描述本次修改"
git push origin master
```

推荐不要直接使用 `git add .`，除非已经确认不会把临时文件、密钥、构建产物或个人文件加入提交。

有 GitHub 账号的成员也不需要再单独推送 GitHub；负责人会统一同步。若团队明确要求某位成员同时推送两个远程，必须先确认本地分支已基于猿舟最新提交，再执行：

```bash
git push origin master
git push github master
```

---

## 7. GitHub 私有仓库邀请

有 GitHub 账号的成员：

1. 登录 GitHub；
2. 打开 GitHub 通知或邀请邮件；
3. 接受私有仓库邀请；
4. 确认可以打开仓库页面。

没有接受邀请时，不能访问或推送私有仓库。邀请 GitHub 账号不会自动赋予猿舟权限；猿舟权限需要在猿舟项目的成员设置中单独配置。

---

## 8. Merge Request（合并请求）

如果猿舟项目页面显示 **Merge requests**，可以采用分支和 MR 流程：

```bash
git switch -c feature/简短功能名
git add <文件>
git commit -m "feat: 增加某项功能"
git push -u origin feature/简短功能名
```

然后在猿舟项目中创建 Merge Request：

- 源分支：`feature/简短功能名`；
- 目标分支：`master`；
- 描述修改内容、验证方式和可能风险；
- 指定负责人或同学审查；
- 审查通过后再合并。

如果项目没有显示 Merge requests，或项目权限不允许创建 MR，则按团队约定直接向 `master` 提交，但仍必须先拉取最新代码并遵循提交规范。

---

## 9. 仓库负责人同步到 GitHub

猿舟有新提交后，仓库负责人执行：

```bash
cd /d D:\laptop-learning\企业实训\project\issedu_ysu2026_7439
git pull --ff-only origin master
git push github master
```

如果远程名称尚未配置：

```bash
git remote add github https://github.com/<GitHub用户名>/<仓库名>.git
git push github master
```

如果 GitHub 曾经单独提交过 README 或其他文件，不能直接强制覆盖。先执行：

```bash
git fetch github --prune
git branch backup-before-github-merge
git merge github/master --allow-unrelated-histories
```

有冲突时先解决冲突、提交合并结果，再推送两个远程。禁止使用 `git push --force` 覆盖团队提交。

---

## 10. 常用检查命令

```bash
git status
git remote -v
git branch --show-current
git log --oneline --decorate --graph -10
git fetch origin --prune
git fetch github --prune
```

遇到问题时，把上述命令的输出和完整错误信息发给仓库负责人，不要只截取最后一行。
