# LLM / 数字人模块 2026-08-31 工作日志：答非所问链路治理与本地模型回归

**负责人**：海瞳 LLM 组（LLM / 数字人协同）  
**工作范围**：本地 Ollama 对话链路、RAG 检索与兜底、追问上下文、前端 SSE 展示。  
**模型基线**：`ds-ocean_mingzhe:latest`（本轮未修改模型权重；备份为 `ds-ocean_mingzhe:v1-0829-backup`）。

## 一、用户反馈与复现现象

本轮针对“答非所问、直接输出知识库原文、部分问题答不上来、模型自己生成的追问无法回答”等反馈做了端到端检查。真实 Ollama 探针确认本地模型本身可以正常响应，但在部分请求中会出现以下协议和内容问题：

- `message.thinking` 含有较长内部推理，正文为空或正文夹在未闭合的 `<think>` 标签后；
- `done_reason=length` 时仍被旧链路当作成功答案；
- 流式响应缺少 `[DONE]`、JSON 行损坏或只返回思维内容时，页面可能留下半截气泡；
- 向量召回会把相邻主题（例如微塑料、溢油、健康风险）拼到当前问题；
- 兼容消息体没有稳定补入当前轮，追问可能丢失上下文或重复当前问题；
- 建议追问只按索引下发，未验证问题是否真的有可回答证据。

## 二、已完成修复

### 1. Ollama 协议与回答质量门禁

- 在 `src/LLM/chat_api.py` 统一过滤 `message.thinking` 和 `<think>...</think>`，未闭合标签的剩余内容也不向用户展示；
- 非流式和流式响应统一校验可见正文、`done_reason`、JSON 完整性和 `[DONE]` 收尾；
- 空答、thinking-only、截断、缺少结束标记、非法 JSON 统一转为 `invalid_model_output`，交由确定性规则或知识库兜底；
- 流式门禁通过后才发出正文，避免先展示错误残片再回退。

### 2. RAG 主题与意图隔离

- 在 `src/LLM/rag/lexical_retriever.py` 增加鱼类、蓝碳、ROV、重金属等实体主题约束；
- 增加定义、健康风险、处置/复核、操作流程等意图 profile，优先选同主题且同意图证据；
- 单实体短问锁定最高相关来源，避免向量 Top-K 把邻近文档带入答案；
- `src/backend/services/llm.py` 对模型证据做主题和句子意图筛选，并保留报告上下文，防止报告问题退化成通用摘录；
- 增加确定性规则、重复答案门禁和建议追问可回答性检查，创作类请求不再直接复述知识库。
- 对明确并列问法增加实体级保底：每个点名主题至少保留一个最高相关来源，并按用户提问顺序分别回答，避免第二主题被高分文档吞掉。

### 3. 路由、前端和数字人状态

- `src/backend/routers/chat_router.py` 修复旧/现代消息体的当前问题遗漏与重复，保留追问历史主题和报告权限上下文；
- 模型正文缓冲后统一过质量门禁，失败时清理空助手气泡并给出可控错误事件；
- `src/frontend/src/services/api.ts` 严格解析 SSE，只接受约定的 JSON data 事件并要求 `[DONE]`；
- `src/frontend/src/pages/Assistant.tsx` 仅在完整回答后生成建议追问，停止或失败时清理残片、复位数字人状态；
- 导出记录保留关联报告上下文和附件信息，避免导出后丢失对话依据。

## 三、真实模型探针结论

- Ollama 服务：`http://localhost:11434`，服务可用；
- 模型：`ds-ocean_mingzhe:latest` 可加载并完成请求；
