## 问题 1 排查：听筒停不了播报

### 根因链（三条叠加）

1. **语义错位（设计缺陷）**：`toggleMute` 只做 `setVolume(0)`（静音）+ `speechSynthesis.cancel()`，从不打断数字人当前语音。真正能打断的 `interactiveIdle()` 只接在"停止生成"按钮上，而该按钮仅在流式生成中（busy）显示；回答生成完进入朗读阶段时 busy 已复位——听筒成了唯一音频控制点，必现。
2. **SDK 方法名大小写不匹配**：拉取星云 CDN 上的 `xmovAvatar@latest.js` 源码比对，SDK 公开方法是**全小写 `interactiveidle`**（内部 `sendApiCall("interactiveidle")`），封装层找的是驼峰 `interactiveIdle`，永远匹配不上，只能降级到普通 `idle()`（回到待机指令，不掐断已缓冲音频）。
3. **静音状态可被 SDK 悄悄解除**：SDK 内部 `visibilitychange` 处理器在切回前台时无条件 `setVolume(1)`，用户静音会被覆盖。

### 修复

**文件**: `src/frontend/src/services/digitalHuman.ts`

- 新增 `stopSpeaking()`：优先调 SDK 顶层 `interrupt("new_speak_start")`（经 SDK 源码确认该调用路由到渲染调度器，清空音频缓存队列并暂停渲染器，能立即掐断已缓冲语音），退而 `interactiveidle`（小写优先，兼容驼峰），最后 `idle`；同时复位 `isSpeaking`/`awaitingVoiceStart` 并清空语音队列。
- `interactiveIdle()` 修正方法名匹配顺序（小写优先）。
- 新增 `setMuted(muted)` + `userMuted` 标记；init 时包装 SDK 实例的 `setVolume`，静音期间任何音量恢复（含 SDK 内部 `visibilitychange`）都被强制压回 0。
- `setVolume` 补 try/catch（原先无保护，SDK 方法缺失时会在点击处理器里抛异常，导致后面的 `speechSynthesis.cancel()` 也执行不到）。

**文件**: `src/frontend/src/pages/Assistant.tsx`

- `toggleMute`：静音 = `setMuted(true)` + `stopSpeaking()` + 清字幕/状态；取消静音 = `setMuted(false)`。按钮 title 同步改为"停止播报并静音"。
- `stop()`、`toggleDigitalHuman()` 的 `interactiveIdle()` 调用统一换为 `stopSpeaking()`。

## 问题 2 排查：导入报告只回"污染等级：良"

### 根因链（三层，全部确认）

用户截图中的回答（"先给结论：污染等级：良……报告没覆盖的判断我不会补写"）与 `src/backend/services/llm.py::_report_solution_response` 输出**逐字一致**——这段话根本不是模型写的，是确定性简报兜底拼的，它只能拼上下文里真实存在的字段：

1. **前端导入的是"假报告"**：`importSystemReport` 把报告列表的元数据（标题/海域/时间/等级/评分/目标数/摘要）拼成约 10 行 MD 上传知识库；真正的 HTML 报告（逐图明细、类别/材质分布、治理建议）从未进入知识库或上下文。回答里"污染等级：良"正是从这份合成 MD 的 `- 污染等级：良` 行解析出来的。
2. **结构化分析快照不存在**：后端 `_build_report_context` 注入 = 报告元数据 + summary + `ReportAnalysis` 快照；RPT-10 无快照记录，上下文里明写"该报告尚未完成结构化分析，请明确说明"。
3. **分析接口是死接口**：`ReportAnalysis` 只有 `POST /reports/{id}/analyze` 会生成，前端 `api.analyzeReport` 定义了但全工程零调用——快照永远是空的。

反幻觉门禁本身工作正常（模型自由发挥会被 `finalize_model_answer` 拦下换成快照兜底），数据链路断了才是病根。

### 修复（前端，后端零改动）

**文件**: `src/frontend/src/pages/Assistant.tsx`

- `importSystemReport` 导入系统报告时**先调用 `api.analyzeReport(reportId)`**（`POST /reports/{id}/analyze`）生成结构化分析；失败（无权限/摘要不匹配 422 等）自动回退元数据简报，不阻塞导入。
- 新增 `buildReportImportMarkdown()`：把"元数据 + 分析快照（关键发现/可能来源/P0-P2 处置方案含责任人时限/后续监测）"拼成导入 MD，**小节标签与后端 `_report_briefing_sections` 解析口径逐一对齐**（关键发现/可能来源/处置方案/后续监测/分析摘要/评分/目标数量），导入后追问与首轮分析都能得到完整结构化回答。
- 附带收益：分析快照落库后，绑定 report_id 的**后续追问**在 `_build_report_context` 里也能读到完整快照。

## 问题 3 核实：上下文是做了的（三层）

1. 前端每轮请求带全量 messages 历史 + session_id（`api.ts streamChat`）；
2. 后端 `ChatHistory` 逐条落库，刷新/切页经 `GET /chat/history` 回放；指代追问（"那成本呢？"）有 `is_referential_follow_up` + `_build_retrieval_query` 专门处理；
3. 绑定的 report_id/document_id 每轮随请求注入上下文。

边界：会话级记忆（sessionStorage，一个标签页一个会话），"新建会话"重置，无跨会话长期记忆——符合当前设计定位。

## 增强：流式对话逐句开口 + 字幕同源改造

**前提约定**：SDK 原生字幕已禁用（页面持续隐藏 SDK 字幕 DOM），字幕完全由我们自己的 `og-subtitle-hud` 呈现——所有字幕改造只动我们自己的队列，不依赖 SDK 字幕。

### 旧行为的问题

- 生成期间数字人闭嘴（只有字幕在闪），整段生成完才一次性 `speak(全文)`；
- 字幕在生成期间每条 chunk 都重取"最后一句"来回跳变；播报开始时又按全文重新排一条估算时长的字幕队列——字幕与语音两套节奏，必然错位。

### 新行为

**文件**: `src/frontend/src/services/digitalHuman.ts`

- `speak()` 重写为流式感知：`isStart=false` 的续传片段在会话内直接追加（不排队不打断）；新会话请求在播报中时照旧排队；新增 `awaitingVoiceStart` 状态——首句已发出但还没出声期间，后续片段缓存排队，`voice_start` 时立即补发，防止被 SDK 当作新会话打断；续传片段到达时会话已意外结束则自动升级为新会话起点。
- 新增 `speechActive` getter（`isSpeaking || awaitingVoiceStart`），供页面判断会话状态。

**文件**: `src/frontend/src/pages/Assistant.tsx`

- 新增 `dispatchStreamingSpeech(fullText, final)`：流式 chunk 回调里按"句末标点或换行"切分（`splitSpeakable`），句子一完整就送进 SDK 开口（清理 markdown 符号/列表符后朗读）；`final=true` 收尾时把末尾残句一并送入并结束语音会话，**不再整段重播**。
- 字幕队列重构为**可动态追加的计划队列**（`subtitlePlanRef`/`pushSubtitleLines`）：字幕行与语音句同源同步追加，按行字数估算推进；`speakEnd` 时若计划未走完（生成中途会话被云端提前收尾）保留字幕继续推进，走完才清空。
- `ask()` 收尾分支重写：已逐句开口的不再重复播报，只判状态；静音/离线时只清理。
- 拟态（纯文本）模式的舞台打字机字幕路径保持不变。
