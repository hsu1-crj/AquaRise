# LLM / 数字人模块 2026-09-01 工作日志：数字人长期密钥暴露风险修复

**负责人**：海瞳 LLM 组（LLM / 数字人 / 生命图谱）
**工作范围**：数字人 XmovAvatar SDK 鉴权链路、服务端配置、前端初始化与安全回归。

## 一、问题描述

原数字人初始化代码在 `Assistant.tsx` 和 `GuideDock.tsx` 中读取 `VITE_DH_APP_SECRET`，并将长期 `appSecret` 传给浏览器端 XmovAvatar SDK。Vite 构建后该值会进入前端 JavaScript 产物，测试人员可通过源码或 Network 查看并复用真实平台密钥。

原 `/api/v1/digital-human/config` 仅返回公开配置，没有服务端短期凭证接口，未形成完整的服务端鉴权闭环。

## 二、根因分析

官方 XmovAvatar JS SDK 强制使用 `appId + appSecret` 在浏览器侧计算请求签名，没有直接提供短期 token 参数。若继续把平台长期密钥放入 `VITE_*`，前端构建和运行时都会暴露该凭证。

## 三、修复方案

1. 后端配置 `src/backend/config.py` 只从项目根目录 `.env` 读取 `DH_APP_ID` 和 `DH_APP_SECRET`，不再回读前端 `.env`。
2. 新增受权限保护的 `POST /api/v1/digital-human/credential`，为当前用户签发 5 分钟短期随机凭证，并设置 `Cache-Control: no-store`。
3. 新增 `/api/v1/digital-human/gateway` 服务端签名代理。浏览器 SDK 使用短期凭证签名请求，后端验证后使用真实 `DH_APP_SECRET` 重签，再转发到魔珐星云上游网关。
4. `Assistant.tsx`、`GuideDock.tsx` 改为获取短期凭证，不再读取任何 `VITE_DH_APP_ID / VITE_DH_APP_SECRET`。
5. 删除前端环境变量类型和示例中的长期密钥配置，保留无凭证时的全息拟态/浏览器语音降级能力。

## 四、配置说明

真实配置只放在项目根目录 `.env`：

```env
DH_APP_ID=平台控制台获取的 AppID
DH_APP_SECRET=平台控制台获取的 AppSecret
```

不要在 `src/frontend/.env` 中填写 `VITE_DH_APP_ID` 或 `VITE_DH_APP_SECRET`。旧密钥曾经进入前端配置时，应在平台控制台轮换后再进行联调。
