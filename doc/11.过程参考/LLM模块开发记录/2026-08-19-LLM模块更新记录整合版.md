## 四、LLM 回答链升级

### 4.1 完整链路

```
用户问题
  → 【1】确定性规则 direct_response()
  │     身份/寒暄/父母/范围外/置信度/幽灵渔网/塑料降解/微塑料/MARPOL/清理方案 命中 → 直接返回
  → 【2】领域判断 is_domain_question()（海洋词表，未命中 → 友好范围说明）
  → 【3】RAG 检索（向量优先 ChromaDB+BGE-small-zh-v1.5；依赖缺失自动降级本地词法检索）
  │     证据格式： [S1] 来源：某某知识.md \n 正文…
  → 【4】ds-ocean_mingzhe（Ollama，temperature 0.2，think=False，_ThinkFilter 流式过滤）
  → 【5】引用/事实质量门禁 is_acceptable_model_answer()  ← 先缓冲整段，验证后才允许输出
  → 【6】通过 → 短句流式输出；未通过 → 知识库保守兜底 _knowledge_fallback()
  → 【7】chat_history 持久化
```

实现位置：`chat_router.py` 的 `/api/v1/chat` 事件流（先缓冲模型输出 → `finalize_model_answer()` 统一后处理 → 通过门禁才按短句 `stream_text()` 输出，不合格内容**不会先泄漏到 UI**）。

### 4.2 知识库证据注入（`chat_api.py` `RAGService.retrieve`）

检索结果统一格式化为：

```
[S1] 来源：海洋塑料治理技术综述.md
（正文片段）

[S2] 来源：MARPOL公约解读.md
（正文片段）
```

`[S{id}]` 编号与注入顺序一一对应，供模型引用、门禁校验、前端溯源。

### 4.3 模型硬约束（服务端系统消息，客户端 system 无法覆盖）

有证据时注入的"唯一允许使用的事实证据"约束（`ChatService.prepare_messages`）：

1. 先直接回答用户问题，再给依据或行动建议；
2. **每个包含事实判断的自然段末尾标注来源编号**，如 `[S1]`；
3. **不得补写证据中没有的数字、机构、法规条款、因果关系或健康结论**；
4. 证据不足时明确说资料不足，不要依靠模型记忆补全；
5. 不要大段照抄，**回答控制在 500 个汉字以内**。

无证据时注入：除身份、寒暄和范围说明外，不得依靠模型记忆回答事实问题，直接说明资料不足并请用户补充信息。

身份约束同时固定：仅被问到"谁开发/谁做的"才回答"海瞳团队的实训项目，LLM 模块由海瞳 LLM 组负责"；被问到"父母/家人"用轻松口吻说明无生物学家人；不主动提及项目背景；不输出 `<think>` 标签、推理过程或内部提示词。

## 五、质量门禁增强（`src/backend/services/llm.py`）

### 5.1 旧 → 新对比

| 检查项 | 旧 | 新 |
|--------|----|----|
| 空答案 / 完全复述问题 | ✅ | ✅（保留，`len < 24`、`text == query`、前缀复述） |
| 推理泄漏 `<think>` | ✅ | ✅（保留，路由层 `_strip_think` + `is_acceptable_model_answer` 双保险） |
| 短句循环重复 | ✅ | ✅（保留，8/10/12 字片段出现 ≥4 次拦截） |
| 关键术语必备要素 | ✅（微塑料/MARPOL） | ✅（保留：微塑料→5毫米/碎片/颗粒/小于；marpol→附则/公约/船舶） |
| 引用编号真实存在 | ❌ | ✅ `citation 不在 [1, len(evidence)] → 拒绝` |
| 每个实质段落都有引用 | ❌ | ✅ `_claims_have_citations()`：逐行检查，正文行必须含 `[S#]`，标题/冒号结尾/短行除外 |
| 引用内容支撑回答 | ❌ | ✅ 行内断词（2-gram 去停用词）与所引证据的交集占比 **≥ 16%**，否则拒绝 |
| 数字必须见于问题或知识库 | ❌ | ✅ `_has_unsupported_facts()`：答案数字集合 −（问题+证据）数字集合非空 → 拒绝（先剔除引用编号与列表序号） |
| 机构名称不得编造 | ❌ | ✅ `_UNSUPPORTED_ORG_RE`：`××委员会/研究院/保护署/管理局/协会/组织/大学` 必须整体出现在问题或证据中 |
| 长度限制 | ❌ | ✅ 有证据回答 `len(text) > 800 → 拒绝`（提示词层再限 500 汉字） |
| 单引用滥用整篇 | ❌ | ✅ 每个实质性段落/列表项都必须同一行给出自己的来源编号，杜绝一个 `[S1]` 装饰整篇幻觉 |
| 无证据时的要求 | ❌ | ✅ 有证据分支为空时，回答必须含"资料不足/没有足够资料/暂时无法确认/未检索到" |
| MARPOL 知识边界 | ❌ | ✅ `(允许|可以|能够).{0,12}(塑料|垃圾).{0,12}(倒|排放).{0,8}(海|海里)` → 拒绝 |

### 5.2 不合格时的兜底链

`finalize_model_answer()` → 净化后未过门禁 → `_fallback_response()`：

1. `direct_response()` 确定性规则（身份/置信度/MARPOL 等高危场景直接给权威答案）；
2. `_knowledge_fallback()` 知识库保守提炼：词法检索 Top-3 → 句级打分（问题词重叠 + 来源名次加成 + 行动词加成）→ 截取 ≤650 字、最多 4 句 → 标注"资料来源：××.md"；
3. 最终友好提示："嗯，这个问题我暂时还没有足够的资料来确认…"。

即：**不合格回答永远不会直接返回模型结果**，用户只会看到确定性答案、知识库保守答案或明确的信息不足说明。

## 六、RAG 检索优化（`src/LLM/rag/lexical_retriever.py`）

词法排序公式（`LocalKnowledgeRetriever.search`）：

```python
score = overlap / sqrt(max(1, len(item["terms"])))   # 基础词重叠（归一化）
      + phrase * 0.04                                  # 长词短语命中
      + title_overlap * 0.12                           # ① 文件标题匹配加权
if action_query:                                       # ② 行动类问题
    score += 0.18 × 命中数（源头/减量/拦截/清理/回收/复测/监测/记录/评估/管理）
if len(content) < 90:  score *= 0.7                    # ③ 仅标题、缺正文的短片段降权
score >= 0.10 才入选                                   # ④ 弱相关过滤
```

四项优化效果：

| 优化 | 机制 | 解决 |
|------|------|------|
| ① 标题权重 | `title_overlap × 0.12` | 文件名（如"海洋塑料治理技术综述.md"）与提问强匹配时排名提升 |
| ② 行动类加权 | `治理|措施|处理|清理|怎么做|如何|建议|流程` 命中后按行动词加分 | "海洋塑料怎么治理/清理/回收"类问题命中治理型文档 |
| ③ 短片段降权 | `<90 字 × 0.7` | 只有标题、无正文的片段不占据前列 |
| ④ 弱相关过滤 | `MIN_RELEVANCE_SCORE=0.10` | 常见汉字偶然命中不计入，**"海洋塑料治理"不再错误命中 MARPOL 或泛生态说明**；"今天天气怎么样？"检索为空（回归断言） |

配套：`RAGService`（`chat_api.py`）保持"向量优先、词法兜底"自动降级；文档按 `#~###` 标题边界分块、900 字滑窗，避免跨主题拼接；HTML 文档剥标签后分词。
