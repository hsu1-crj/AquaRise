# LLM 模块 2026-08-28 工作记录：渔网处置卡修复与答案内复读门禁

**负责人**：海瞳 LLM 组（LLM/数字人协同）
**触发背景**：真机提问“发现幽灵渔网怎么处理？”未命中安全处置卡，落入本地 1.5B 模型后出现多节近义复读；现有质量门禁只能比较本轮与上一轮答案，不能识别本轮内部换词复述。
**方案基线**：只调整运行时路由和质量门禁；底层模型保持本地自训练 `ds-ocean_mingzhe`；不训练、不接入云端 API、不修改推理参数；`_atlas_species_context_response` 生命图谱物种档案路由保持原样。

## 一、病根诊断

1. **处置意图被操作意图抢占**：`src/backend/services/llm.py::_direct_response_core` 中，`net_operation_intent` 同时包含“怎么处理/如何处理/方法”等泛化词。“发现幽灵渔网怎么处理”因此被当作专业切割作业问题，`not net_operation_intent` 条件不成立，安全处置卡失效。
2. **本轮内部复读无检测**：`is_near_duplicate_answer` 只比较当前候选答案与上一轮 assistant 回答；`_has_obvious_repetition` 只检查 8/10/12 字片段是否出现至少 4 次。两个长段落仅出现一次、但整体高度相似时会被放行。
3. **蓝碳边界词缺失**：验证要求“什么是蓝碳”进入 RAG + Ollama 链路，但 `DOMAIN_TERMS` 只有“碳汇”没有“蓝碳”，问题会先被范围拒答卡截走。

## 二、修复内容

### A. 渔网处置卡意图归位（`src/backend/services/llm.py::_direct_response_core`）

- `net_operation_intent` 只保留 `切割|微创|rov|潜水员|操作|指引|标准作业|程序|步骤|方案|sop|细节`，专业作业问法继续进入既有作业卡或模型链路。
- `net_disposal_intent` 增加 `怎么处理|如何处理`，普通发现/现场处置问法稳定命中安全卡。
- `清洗|脱盐|再生|利用|回收` 守卫未改，“渔网怎么回收”不会被安全处置卡抢答。

### B. 段落级近重复门禁（`src/backend/services/llm.py::_has_near_duplicate_segments`、`_has_obvious_repetition`）

- 在既有 `_has_obvious_repetition` 中扩展段落检测，没有另建独立兜底链。
- 按空行或列表项边界切分答案，兼容 `1.`、`一、`、`(1)`、`（一）` 等编号；移除项目符号/序号后再去空白、标点并统一小写。
- 仅检查总归一化长度不少于 200 字、单段不少于 40 字、长度比例不少于 0.60 的段落对；使用 `difflib.SequenceMatcher` 比较，相似度大于 `0.70` 判为复读。
- 命中后沿用 `is_acceptable_model_answer` 的既有拒绝路径，使请求自然退到证据补丁、知识库摘录或友好未知回答。
- 旧有短片段出现 4 次的循环检测继续保留；新段落检测对短答案不生效，降低正常简答和列表误杀概率。

### C. 蓝碳问题恢复模型链路（`src/backend/services/llm.py::DOMAIN_TERMS`）

- 只补充领域词“蓝碳”，未新增确定性答案卡。
- “什么是蓝碳”现在跳过范围拒答，继续执行 `ChatService.prepare_messages → 强证据判断 → ds-ocean_mingzhe → finalize_model_answer`。

### D. 回归测试（`tests/test_llm_style_upgrade.py`）

- 新增 3 条处置问法正向用例。
- 新增 ROV 切割作业、渔网回收和蓝碳模型链路守卫。
- 新增长段落近义复读拒绝样本（含括号编号列表）、短答案阈值样本，以及正常长篇垃圾类型列举放行样本；蓝碳同时断言领域识别与未被确定性卡抢答。

## 四、遗留与说明

- 段落近重复阈值取保守值 `0.70`。低于该相似度的松散语义复述可能仍被放行，这是为避免误杀正常长列举而保留的边界；后续若积累到真实漏网样本，再基于样本下调阈值。
- 新检测依赖空行或列表项边界；无分段的单段循环仍由原有短片段重复规则处理，不做重型语义模型判断。
- `操作|指引|标准作业|程序|步骤|方案|细节` 仍按既定方案保留为作业意图词；因此“处置步骤/处理方案”这类带作业细化色彩的问法不会被普通安全卡抢答。若产品后续希望这类问法也直接给安全卡，需要另行拆分“专业信号 + 泛化细节词”的组合规则。
- “蓝碳”仍由 RAG + 本地小模型回答，内容上限取决于知识库证据和模型能力；本轮只修复错误拒答，不编写新的硬编码科普卡。
- `_atlas_species_context_response` 未修改；未改 `src/LLM/chat_api.py`、推理参数或模型配置；未接入任何云端 LLM/API。
- `_diag_llm.py`、pytest 临时目录等中间产物均已清理，不入库。
