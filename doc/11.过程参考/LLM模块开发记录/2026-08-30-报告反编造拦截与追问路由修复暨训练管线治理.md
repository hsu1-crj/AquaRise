# LLM 模块 2026-08-30 工作记录：报告反编造拦截与追问路由修复暨训练管线治理

**负责人**：海瞳 LLM 组（LLM/数字人协同）
**触发背景**：浏览器实测海洋守护者对话（数字人保持纯文本模式，未消耗数字人积分），发现三类缺陷：① 问"我最近的检测报告结论是什么？污染等级高吗？"模型凭空编造"污染等级[高]、铅汞镉超标"——平台真实报告仅 RPT-9（等级中，68 分，46 件）与 RPT-8（优，92 分，0 件），属硬幻觉；② 指代追问"你说的分段解缠，具体是怎么操作的？""那成本呢？"两次被误判领域外，答"这题我不是行家"，追问闭环失灵；③ "PET 瓶和普通塑料袋哪个在海里更难降解"回避对比结论，结尾挂模板化免责。另按指示对本地 `ds-ocean_mingzhe` 做后训练，彻查"模型是否特别糟糕"。
**方案基线**：线上模型永远叫 `ds-ocean_mingzhe`——本轮只产出同名候选权重 tag `v2`，达标才切 `latest`，全程保留 `v1-0829-backup` 可一键回滚；qwen3 仅作为对照评测对象，不训练、不接入平台；链路层只调路由与门禁，不改推理参数与接口协议。

## 一、病根诊断

1. **追问被范围兜底抢答**：`services/llm.py::is_domain_question` 只看当前消息，"那成本呢？""你说的分段解缠…"不含任何 DOMAIN_TERMS，`_direct_response_core` 末尾 `not is_domain_question → scope_response()` 直接截走，模型链路从未收到这些问题。原始模型带上下文裸测本可正确接住追问，问题纯在路由层。
2. **报告数据无事实来源也放行**：未绑定报告时 `report_context=None`，模型拿不到任何真实报告事实；质量门禁 `_has_unsupported_facts` 只核对数字/机构/书名号专名，"污染等级[高]、重金属浓度超标"不含数字特征，直接放行。
3. **对比题触发词缺失**：塑料瓶/袋降解对比卡的触发正则只覆盖"哪个先/快降解"，不含"更难降解/更慢/更持久"句式；原卡片文案本身也拒绝给出排序结论。
4. **训练管线双重缺陷（后训练阶段发现）**：`train_lora.py::tokenize_fn` 从未把 target 拼进 `input_ids`，label 只覆盖 prompt 尾部——每条样本实际只有 1 个监督 token（预测 `</think>`），历史所有微调的答案内容（材质事实、拒编造、身份口径）零监督；GGUF 转换后 tokenizer `pre=deepseek-r1-qwen` 与 HF 训练侧分词系统性错位（同一提示词 Ollama 51 token vs HF 44-45 token，CJK 合并未生效）。线上 v1 同样带分词错位，是"长期训了没用"的根因。

## 二、链路修复内容

### A. 追问路由（`src/backend/services/llm.py` + `src/backend/routers/chat_router.py`）

- 新增 `is_referential_follow_up(message, history)`：显式指代词（上面/刚才/你说的/那…呢/具体怎么等）直接判定；存在历史时的 ≤8 字超短问句也按追问处理。
- `direct_response` / `_direct_response_core` / `_fallback_response` / `finalize_model_answer` 增加 `allow_scope_fallback` 开关；`chat_router` 检测到追问时以 `allow_scope_fallback=False` 放行进带历史上下文的模型链路，范围兜底不得抢答。
- DOMAIN_TERMS 补"解缠/分段解缠"；"分段解缠具体怎么操作"现命中既有切割作业卡，获得确定性 SOP 回答。
- `chat_api.py::_FOLLOW_UP_RE` 同步扩展（你说的/那…呢/具体怎么），`_build_retrieval_query` 检索查询随之合并最近上文。

### B. 报告反编造（`chat_router.py` + `services/llm.py`）

- 新增 `_build_recent_reports_context`：报告类问题未绑定具体报告时，按权限自动检索最近 3 份真实报告（摘要 + 结构化分析快照）注入上下文；名下无报告则注入"暂无报告"事实。生产链路中模型从此只能引用数据库事实。
- `finalize_model_answer` 新增反编造门禁：答案中的等级/评分/重金属/超标断言必须能在报告上下文中找到同源依据（`_ungrounded_report_claims`），否则整段退回报告快照摘录或"没有可核对的报告上下文"诚实话术，编造内容一个字不留。
- `is_acceptable_model_answer` 接受 `report_context` 作为数字核对依据；`_has_unsupported_facts`/`_patch_with_evidence` 贯穿 `extra_context`。

### C. 对比题（`services/llm.py`）

- 触发词扩展：`更难降解|更慢|更持久|哪个…难/慢` 等句式纳入塑料瓶/袋对比卡。
- 卡片文案改为直给结论：PET（约 450 年量级）整体比塑料袋更难降解，同时声明"区间重叠、数量级判断不是精确名次"、碎裂成微塑料而非真正消失、回收路径差异。

### D. 追问兜底承接话题（`services/llm.py` + `chat_router.py`）

- `finalize_model_answer` / `_fallback_response` 增加 `history_note`（取上一轮 assistant 回答）；追问被门禁拦截落到兜底时走新增的 `_followup_topic_unknown`：明确承接上文话题（"结合刚才聊到的'渔网回收…'——你追问的这一点我手头没有可核验的资料…"），并邀请补充条件，不再像新问题一样答非所问。

### E. 压测补强：实时信息边界卡与健康关切卡（`services/llm.py::_direct_response_core`）

压测中发现两处答非所问，补确定性卡片：
- **实时信息边界卡**（`_realtime_info_response`）："昨天新闻说渤海发现巨型垃圾带"这类不可核实消息，原落范围兜底答非所问。现在明确"拿不到实时新闻、无法核实，既不确认也不否认"，并给出求证路径（官方通报/权威媒体交叉）与"导报告用真实数据研判"的下一步，绝不顺着编。
- **健康关切卡**（`_health_concern_response`）：儿童误吞海水担心微塑料的问题，原落到知识库摘录答非所问。现在先安抚（"偶发摄入目前没有证据表明造成急性伤害"），再给可执行指引（观察症状、出现再就医、12320 热线），不编造医学结论；带个人/亲历语境限定，不抢"微塑料对人体的危害"类通用科普问法。
- 附带修复：`_report_context_fallback` 会把注入上下文的门禁说明行（"只能使用这些事实"）当报告内容摘出来展示，新增 `_REPORT_CONTEXT_LINE_SKIP_RE` 过滤。

### F. 舞台打字机字幕（`src/frontend/src/pages/Assistant.tsx`）

- 原字幕仅在真数字人模式显示，且按"每字 230ms"估时整句硬切、答完即消失；纯文本/拟态模式舞台上没有任何字幕。
- 新增与流式回答同步的打字机字幕（`pushStageChunk`/`runStageTyper`/`endStageStream`）：模型吐字按 ~55 字/秒逐字揭示、只显示最近 150 字窗口、答完停留 2.6 秒自动淡出；纯文本/拟态/静音模式全部生效，真数字人模式保持原队列逻辑不变。停止生成、组件卸载路径同步清理定时器。

### G. 绑定报告方案简报生成器（`services/llm.py`）

- 问题：绑定报告后问"治理解决方案"，小参数模型对报告上下文的回答跑成通用范文并被门禁拦截，兜底只剩几行摘录复述——用户要的是分析解读，得到的是复读。
- 链路修正：`is_acceptable_model_answer` 对绑定/注入报告上下文放宽两条 RAG 专属检查（[S编号] 强制引用、`_evidence_supports_requested_intent` 意图否决——报告事实自带出处且不依赖 RAG 命中），硬幻觉防线（数字/机构/事件对照报告上下文）保留。
- 兜底升级：新增 `_report_briefing_sections` + `_report_solution_response`——模型答案仍被拦时，方案/解读类问题直接用快照实测事实组装"结论（等级/评分/数量）→ 概况 → 关键发现 → 可能来源 → 处置方案（含责任人与时限）→ 后续监测建议"结构化简报，零幻觉且可直接执行。
- 配套修复：`_build_report_context` 绑定上下文补充"生成时间/检测海域（经 sea_areas 解析）/关联任务"事实行；报告上下文存在期间跳过复读门禁替换（同报告连续追问高相似是预期）；`_report_context_fallback` 过滤门禁说明行与悬空标签行。

### H. 报告随消息发送的附件化呈现（`src/frontend/src/pages/Assistant.tsx` + `styles.css`）

- 用户反馈：绑定状态以横幅悬浮在聊天框上方、且发送的消息看不出"文件和文字一起发过去了"。
- 改为附件化交互：发送消息时把绑定报告写进消息对象（`attachment`），用户气泡内渲染"📄 报告名 + 摘要 + 已随消息发送"附件卡片，文件与文字在聊天记录里一体化呈现；数据层 `report_id`/`document_id` 本就随每条请求携带，无需后端变更。
- 移除聊天区顶部的绑定横幅，绑定状态收进"导入质量分析报告"按钮（绑定后变为"更换报告 + 报告名胶囊，点胶囊解绑"），不再占用聊天区空间。
- 回答排版统一升级：结论段自动渲染为结论卡；"概况/关键发现/可能来源/处置方案/后续监测"小节自动收进带侧边条的小卡片；P0/P1/P2 项渲染彩色优先级徽标；关键字（等级/评分/数量/法规专名）青色高亮——全部渲染层确定性完成，对所有回答生效。

## 五、遗留与说明

1. **llama.cpp 对 DeepSeek-R1-Distill-Qwen 分词器的 CJK merge 失效**为工具链级遗留问题（也是当初暂缓上线的原因）：裸模型在部分问法上仍会编造，平台由链路门禁兜底。v2 权重 HF 侧已达标，后续可用 llama-cpp-python/HF 直接推理对比，或待 llama.cpp 修复后重转权重（重训兜底仅 8 分钟）。验证中间产物已随冗余清理移除，重转换可按第三节流程自 merged 权重重新生成。
2. 当前 `latest`=v2 权重（用户决策上线；平台经 `ds-ocean_mingzhe` 无 tag 名自动解析到 `latest`，切换零配置变更）；如需回滚，`ollama cp ds-ocean_mingzhe:v1-0829-backup ds-ocean_mingzhe:latest` 一键回到 v1。
