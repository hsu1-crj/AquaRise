# LLM / 数字人模块 2026-09-01 工作日志：海洋守护者流式气泡与切页状态修复

**负责人**：海瞳 LLM 组（LLM / 数字人 / 生命图谱）  
**工作范围**：海洋守护者前端流式渲染、切页在途状态恢复、LLM / RAG、数字人和生命图谱快速回归。  
**用户反馈**：发送问题后 AI 回答气泡长期空白；切换到其他页面再返回时，回答内容才出现。

## 一、问题复现

复现路径：登录平台 → 进入「海洋守护者」→ 输入任意问题并发送 → 等待回答生成。首次停留在页面时，AI 气泡没有正文；切换页面后返回，历史接口会立即显示已经落库的回答。

该现象说明后端生成和落库链路正常，故障位于当前页面实例对 SSE 流式增量的消费与 React 状态更新之间。

## 二、根因与修复

### 1. StrictMode 首次清理后挂载标志未恢复

`src/frontend/src/main.tsx` 使用 `React.StrictMode`。开发环境下 React 会执行一次 `setup → cleanup → setup` 的生命周期检查。`Assistant.tsx` 的清理函数把 `mountedRef.current` 设为 `false`，第二次 setup 却没有恢复为 `true`。

因此，接口返回的每个 SSE chunk 都能正常累积到模块级 `inFlightChat`，但会被 `if (!mountedRef.current) return` 拦截，无法调用当前页面的 `setMessages`。切页重挂载后，页面从历史接口读取已落库答案，于是表现为“必须切页才显示”。

修复内容：

- 在资源生命周期 effect 的每次 setup 阶段明确设置 `mountedRef.current = true`；
- cleanup 阶段继续设置为 `false`，保证真正卸载后不再更新旧组件实例；
- 使用临时 StrictMode 回归用例验证当前页面无需切页即可直接渲染流式回答正文；验证完成后按仓库清理要求移除临时测试文件。

### 2. 切页返回后未恢复生成中状态和停止能力

快速巡检发现，在回答生成途中切页再返回时，新页面虽然能订阅模块级增量，但 `busy` 仍为 `false`，且新组件拿不到原请求的 `AbortController`。这会导致停止按钮消失，并可能允许上一条回答尚未结束时再次发送问题。

修复内容：

- `InflightChat` 保存原请求的 `AbortController`；
- 重挂载检测到同会话在途流时，恢复 `busy`、活动气泡 ID 和控制器；
- 在途流完成或中止后同步释放忙碌状态和控制器；
- 使用“生成途中切页 → 返回 → 点击停止”的临时回归用例确认原请求被正确中止；验证完成后按仓库清理要求移除临时测试文件。
