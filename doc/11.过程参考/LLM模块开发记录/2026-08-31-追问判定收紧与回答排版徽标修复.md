# LLM 模块 2026-08-31 工作记录：追问判定收紧与回答排版徽标修复

**负责人**：海瞳 LLM 组（LLM / 数字人协同）
**触发背景**：按计划对对话模块做检修（原拟多 agent 并行审计）。实机快检发现两处缺陷；同时实测确认平台 agent 并发限额为账号级 1，多 agent 深审计只能串行推进。
**方案基线**：只修路由判定与渲染层；模型权重与门禁架构不动（v2 权重沿用 08-30 上线版本）；每处修复必须有实机验证或正反例快检背书。

## 一、检修发现与修复

### A. 追问判定误伤（`services/llm.py::is_referential_follow_up`）

- **缺陷**：超短追问阈值取"归一化后 ≤8 字"过宽——"塑料袋降解要多久？"（8 字，自含主题的新问题）、"帮我写个治理方案"都会在有历史时被误判为追问；"你好"等纯寒暄也被计入。
- **影响面**：误判为追问后跳过范围兜底，域外短句会落到模型链路得到"资料不足"式回答而非礼貌收窄；域内短问与寒暄因既有分支恰好无害，但判定语义仍是错的。
- **修复**：阈值收紧至 ≤6 字（"那成本呢""具体怎么操作""为什么呀"等典型追问全覆盖）；新增纯寒暄排除（你好/您好/嗨/hello/在吗/早上好等直接按常规路由）。
- **快检**：11 项正反例全过——误伤组（塑料袋降解要多久/帮我写个治理方案/微塑料对人体有害吗/今天天气怎么样）全部不再误判，正例组（那成本呢/你说的分段解缠怎么操作/其中哪个最严重/继续说说/它有什么危害/为什么呀/那怎么办）全部保留。

### B. 回答排版徽标缺陷（`Assistant.tsx::cardifyAnswer`）

- **缺陷一**：优先级徽标（P0/P1/P2）只挂在"游离列表"分支上，"处置方案"等小节被包进侧边条卡片后，卡内列表走不到徽标逻辑——最常见的简报场景（P0 复核/P1 清理/P2 复测）恰好没有徽标。
- **缺陷二**：徽标插入无防重护栏（流式渲染期间 DOM 随 dangerouslySetInnerHTML 重建，实际不致重复，但任何 effect 重入都会叠出 "P0P0P0"）。
- **修复**：抽出 `decoratePriorityList(list)` 统一处理，`querySelector('.og-pri-badge')` 防重入，小节卡包裹后对卡内列表补跑徽标。
- **实机验证**（绑定 RPT-9 发"治理解决方案"）：恰渲染 P0、P1、P2 各一枚，无重复；附件卡、5 张小节卡片、结论卡同时在场。

## 二、边界探针与清理

- **API 边界探针**（登录态直打）：纯空格消息 → SSE error 事件"消息不能为空"并正常 [DONE] 收尾；`report_id=99999` → 404"报告不存在"；`report_id="abc"` → 422 参数校验。均不崩溃、不泄漏堆栈。
- **知识库清理**：绑定重试过程中产生的 3 份"质量报告_RPT-9.md"重复文档，经 `/api/v1/knowledge/{id}` 正规删除（文件、DB 记录、检索索引同步移除），避免污染 RAG。

## 三、多 agent 检修的组织情况

- 原拟 4 路并行（后端链路静态审计 / 训练线审计 / 前端页审计 / API 集成实测），实测平台并发限额为**账号级 1**：首批 4 个全部被"concurrency limit"拒绝。
- 改为串行：后端链路静态审计已启动运行（重点：报告反编造正则的误伤/漏拦面、追问路由边界、简报解析健壮性、SSE 异常路径、并发状态）；训练线、前端页、API 实测三项排队，视其结果决定是否补跑。
- 教训：多 agent 方案在本平台需按"并发 1"设计——要么精简为单 agent 深审，要么接受串行时延。
