# 视觉模型训练评估报告

## 1. 交付范围

本次交付为 TrashCan 1.0 Instance Version 的 22 类水下垃圾目标检测基线。训练采用 YOLO11n 预训练权重，数据集按 train/val/test = 5048/1442/722 划分。

## 2. 训练配置

| 参数 | 值 |
|---|---|
| 模型 | YOLO11n |
| epochs | 50 |
| batch | 16 |
| imgsz | 640 |
| device | CUDA device 0 |
| workers | 0 |
| seed | 0 |
| experiment | underwater_baseline_v1 |

可复现入口：`python -m src.vision.train`。训练结果保存在本地 `runs/detect/underwater_baseline_v1/`，不提交权重和数据集文件。

## 3. 结果

验证集最后一轮指标：Precision 0.8615、Recall 0.8542、mAP@50 0.8913、mAP@50:95 0.6886。验证集最佳 mAP@50:95 出现在第 49 轮，数值为 0.6890，因此部署和推理默认使用 `weights/best.pt`。

测试集评估结果：Precision 0.827、Recall 0.843、mAP@50 0.868、mAP@50:95 0.661，共 722 张图片、1265 个实例。测试集相对验证集的 mAP@50 和 mAP@50:95 分别下降约 0.024 和 0.028。

当前结果属于随机帧划分基线。由于同一视频的相邻帧可能被分到不同 split，指标可能高估跨视频泛化能力；后续正式对比应按视频 ID 分组划分，并以独立 test 集进行最终报告。

## 4. 推理交付

- 单图：`python -m src.vision.detect --source <image> --output <result.jpg>`
- 视频：`python -m src.vision.video_process --source <input.mp4> --output <output.mp4>`

两个入口均支持 `--model`、`--conf` 和 `--device` 参数。推理输出和模型文件属于本地运行产物，已由 `.gitignore` 排除。

## 5. 验收结论

训练已完成，模型评估曲线、混淆矩阵和验证集预测样例已生成；视觉模块具备训练、单图推理和视频逐帧推理入口，满足当前阶段代码提交标准。跨视频数据划分、误检漏检案例归因和 ONNX 导出属于下一轮优化事项。

## 6. 严格视频隔离改进实验

为验证随机帧划分带来的数据泄漏风险，新增按文件名 `vid_xxxxxx` 分组的数据集：train/val/test 为 5047/1443/722 张图片，对应 220/62/30 个视频组。同一视频只进入一个 split。模型和训练参数保持与 B0 一致，仅改变数据划分方式。

实验输出：`runs/detect/underwater_grouped_split_v1-3/`。

| 数据集 | Precision | Recall | mAP@50 | mAP@50:95 |
|---|---:|---:|---:|---:|
| A1 Val 最佳（第 39 轮） | 0.3407 | 0.2366 | 0.2187 | 0.1467 |
| A1 Val 最后一轮 | 0.3440 | 0.2104 | 0.2025 | 0.1331 |
| A1 Test | 0.166 | 0.183 | 0.134 | 0.080 |

A1 Test 的 mAP@50:95 为 0.080，明显低于随机帧 B0 的 0.661，确认 B0 指标受到视频帧跨 split 的显著影响。A1 test 缓存还发现 1 个重复标签，Ultralytics 已在评估缓存阶段移除；后续应在数据转换/质量检查阶段显式去重后再训练。

当前不直接将 A1 的低指标归因于模型结构。下一步优先修复标签质量、检查每个视频组的类别覆盖和长尾分布，再依次进行训练周期、增强、输入尺寸和模型规模实验。
